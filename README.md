# Terraform STACKIT Network Area module

Terraform module which manages [STACKIT network areas](https://registry.terraform.io/providers/stackitcloud/stackit/latest/docs/resources/network_area) (SNA), their regional IPv4 configuration and their static routes on [STACKIT](https://www.stackit.de/en/).

This repository is not from the official STACKIT organization.

> **Organization-scoped.** Unlike the other modules in this organization, a network area is
> associated with an **`organization_id`**, not a `project_id`. This module (and its Terratest)
> therefore takes `organization_id`.

## Usage

```hcl
module "network_area" {
  source  = "terraform-stackit-modules/network-area/stackit"
  version = ">= 1.0.0"

  organization_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
  name            = "corp-network-area"

  regions = {
    eu01 = {
      region = "eu01"
      ipv4 = {
        transfer_network = "192.168.1.0/24"
        network_ranges   = [{ prefix = "192.168.0.0/25" }]
        default_nameservers   = ["8.8.8.8"]
        default_prefix_length = 25
        max_prefix_length     = 29
        min_prefix_length     = 24
      }
    }
  }

  routes = {
    internal = {
      region      = "eu01"
      destination = { type = "cidrv4", value = "10.0.0.0/24" }
      next_hop    = { type = "ipv4", value = "192.168.0.1" }
    }
  }
}
```

See [`examples/basic`](./examples/basic) for an example (requires an `organization_id`).

## Composite module

- `modules/area` — the `stackit_network_area` (toggled by `create_area`).
- `modules/region` — `stackit_network_area_region` per region (`for_each` over `regions`), carrying
  the IPv4 transfer network, network ranges, nameservers and prefix lengths.
- `modules/route` — `stackit_network_area_route` static routes (`for_each` over `routes`).

The root wires them together (regions/routes reference the area's `network_area_id`) and, when
`create_area = false`, targets an existing area via `network_area_id`.

## Notes

- **This is for SNA (STACKIT Network Area), not VPC networks.** IP ranges/nameservers live on the
  `region` resource (IaaS API v2), not on the area itself.
- `destination.type` is currently limited to `cidrv4` and `next_hop.type` effectively to `ipv4`
  by the API (the module validates the documented value sets).
- `regions` and `routes` are maps keyed by a **stable identifier**; they reference the area's
  `network_area_id` via the wiring, never a `for_each` over a known-after-apply value.

## Terratest

The `test/` directory holds a Terratest integration test that applies the `examples/basic` root module against a real STACKIT organization (requires `STACKIT_SERVICE_ACCOUNT_KEY` and **`STACKIT_ORGANIZATION_ID`**).

```bash
cd test
go mod init github.com/terraform-stackit-modules/terraform-stackit-network-area
go get github.com/gruntwork-io/terratest@v1.0.1
go mod tidy
go test -v -timeout 45m ./...
```
